# 竞驰管家婆一键资料互传 · 使用说明

---

## 一、这个工具解决什么问题

竞驰管理通和管家婆辉煌都跑在 SQL Server 上，但两边的表结构完全不同：

- 竞驰用自增 `id` 做父子引用（`par_id`），编号可以留空、可以重复、可以含字母；
- 管家婆必须用**级联编号**做父子关系（一级 `00001`、二级 `0000100001`），
  且客户端树的"能否展开"依赖 `soncount / psonnum / bsonnum` 这些字段。
  直接把竞驰的行 INSERT 进管家婆，软件里会出现：树展不开、明细挂不上分类、编号重复、"K 开发提示：flPtypeid"。

本工具的做法是**全部走管家婆官方存储过程**（`p_hh_BasicInsertB/K/E_Commodity`、
`p_hh_BascInsertP_Commodity`、`p_hh_ModInitGoodsStocks_SNMng_Package`、`p_hh_ImportPtypePriceGZ`）。
编号、父引用、拼音码、子级计数由管家婆自己算，导入后可以直接开单。

---

## 二、准备工作

1. **确认实例名**
   - 竞驰：默认 `DESKTOP-8P5G8VQ\SQLEXPRESS`（库 `kspcDefault`）
   - 管家婆：默认 `DESKTOP-8P5G8VQ\SQLSERVER`（账套库如 `HH15new`）
   - 不知道实例名时，在 SSMS 里看连接窗口的"服务器名称"。
2. **确认 sa 密码可用**（工具用 SQL 身份验证，不用 Windows 身份验证）。
3. **关闭管家婆客户端**（导入会临时改 `sysdata.iniover`，客户端占着会话可能失败）。
4. 首次导入建议先点"维护 → 备份基本资料 13 表"，有备份随时能回滚。

## 三、导入流程

### 第 1 步：连源库

| 输入 | 填什么 |
|---|---|
| 实例 | 竞驰所在的 SQL Server 实例 |
| 库名 | `kspcDefault`（或你自建的竞驰账套库） |
| sa 密码 | 该实例的 sa 密码 |

点 **测试连接**。正常会显示：

```
✔ 竞驰账套已识别：ProductCode=kspc 版本=mS.D.08.8.1.1.000 开账=0 期间=1
```

如果显示"未识别为竞驰账套"，说明这个库里没有 `T_base_wldw_inner` 等四张核心表，
不是竞驰账套（或库名填错了）。

### 第 2 步：连目标库

| 输入 | 填什么 |
|---|---|
| 实例 | 管家婆所在的实例 |
| 库名 | 管家婆账套库名（`HH15new` 等） |
| sa 密码 | 同上 |

点 **测试连接**。正常显示：

```
✔ 管家婆账套可用：758 张表，往来单位 883 行
```

### 第 3 步：勾模块

九个模块默认全选，一般不用改。只想补某一块（比如只补条码）就取消其他勾。

| 模块 | 内容 |
|---|---|
| 往来单位 | 客户 / 供应商 / 专柜 / 代理，含层级 |
| 仓库 | 仓库资料（自动平铺，见"已知限制"） |
| 职员 | 员工资料 |
| 商品 | 商品分类 + 商品，含双单位与价格 |
| 库存结存 | 各仓各商品的期初数量与金额 |
| 价格跟踪 | 每个客户 × 每个商品的最近进价/售价/折扣 |
| 条码 | 商品条码，含单位序号 |
| 扩展价格 | 预设售价4/5、会员价、特价 |
| 扩展辅助单位 | 第 3、第 4 单位 |

### 第 4 步：选项

- **增量模式**（默认关）：勾上后，目标库已有的相同自定义编号会被跳过，只导新增。
  第二次及以后的同步建议勾上。
- **导入后清理客户端缓存**（默认开）：删 `localData` 缓存，强制客户端重拉。
- **导入前自动备份目标 13 表**（默认开）：强烈建议保留。

### 第 5 步：点"开始一键导入"

日志会实时显示每一步。全部成功时日志末尾是：

```
导入结果：往来单位 5；仓库 3；职员 2；商品 4；库存结存 4；价格跟踪 2；条码 4；扩展价格 4；扩展辅助单位 2
✔ 全部成功，无失败记录。
```

然后列出目标库各表当前行数，方便你与导入前对比。

### 第 6 步：验证

1. 重开管家婆，进对应账套
2. 基本信息 → 单位 / 商品 / 仓库 / 职员，检查：
   - 左侧树能一层层展开
   - 列表里编号是纯数字（5 位 / 10 位）
   - 双击明细，能看到价格、单位、条码

如果树是空白的，先去"维护 → 清理客户端缓存"，再重开管家婆。

## 四、出错怎么办

| 日志里出现 | 含义 | 处理 |
|---|---|---|
| `rc=-13 系统已经开账，期初…不能录入` | 目标库已开账，官方过程拒收期初 | 工具已自动临时反开账；若仍报，说明还有别的会话连着账套，关掉管家婆和 SSMS 再试 |
| `rc=-17 没有找到父类` | 单位父引用对不上 | 属工具内部问题（父引用映射），把该条日志和源数据发回即可定位 |
| `rc=-3 父类仓库不存在` | 同上（仓库） | 同上 |
| `rc=-5 父类商品不存在` | 同上（商品） | 同上 |
| `rc=-7 仓库不存在或是已作为类仓库存在` | 该仓库在管家婆里是"类仓库"，不能挂库存 | 工具已把仓库平铺；若仍报，检查源仓库 `par_id` 是否有异常的环 |
| `rc=-28 辅助单位1录入的信息有误` | 单位名与换算率不匹配 | 工具已按"同进同退"清洗；若仍报，看该商品 `unit2`/`unitrelation` |
| `✘ 任务中断：源库不是竞驰账套` | 连错库了 | 核对源库名 |
| `连接失败：…08001` | 实例名写错 / 服务没开 | 核对实例名，确认 SQL Server 服务在运行 |
| `连接失败：…IM002` | 找不到 ODBC 驱动 | 装 `ODBC Driver 17 for SQL Server` |

## 五、回滚

"维护"页：

1. **刷新列表** → 看到所有 `_impbak_2026...` 前缀（每个前缀是一次备份）
2. 选中要回的前缀（不选则默认最新一个）
3. 点 **回滚到最近备份** → 确认

回滚逻辑：先校验该前缀下 13 张备份表是否齐全，**不全就中止，一个字节都不改**；
齐全才在事务里全量恢复。13 张表约 13 秒完成。

> 回滚会覆盖这 13 张表的全部当前内容（不只是本次导入的行）。
> 所以导入前新建的备份才有意义，老备份回滚会把中间的业务数据一起抹掉。

## 六、已知限制（重要）

1. **仓库层级被拍平**
   管家婆的库存期初要求仓库是明细仓库；有子仓库的仓库会被当成"类仓库"，库存挂不上。
   所以竞驰的仓库树（如 `CK01 → CK0101`）导入后是平的：`CK01`、`CK0101` 并列在根下，名称不变。
   这是为保证库存能导入做的取舍，属信息损失。

2. **不导的字段**
   品牌（`pp_id`）、部门（`depid`）、季节（`jj_id`）、辅助属性（`prop1~4`）、
   换货率（`barterrate`）、门店属性（`isShop/ShopType/ShopLeveal`）——管家婆无对应结构或需要额外建表。

3. **期初应收应付**
   导竞驰的 `ystotal00 / yftotal00 / yushoutotal00 / yufutotal00`（期初四项）。
   `ystotal` 等运行余额是历史发生额累计，不导。

4. **多单位价格**
   单位 1 的完整价格矩阵（零售/预设1-5/批发/会员/特价/最低）全部导入。
   单位 2/3/4 目前只导零售价（`U2Price` 等），分档价格（`U2Price1..5`）未导。

5. **反向不实现**
   管家婆 → 竞驰暂不做。竞驰商品表 113 个 `NOT NULL` 列，反向需要逐列补默认值，工作量大。
