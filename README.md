# 竞驰管家婆一键资料互传

把 **竞驰管理通**（标准版 v8.1，库 `kspcDefault`）的基本资料，一键导入 **管家婆辉煌 TOP15** 账套。

> 这是"多软件适配器"框架的第一个落地实例：千业管理通（Bas）是第一类，竞驰管理通（KSPC）是第二类，
> 二者共用同一套管家婆官方过程通道，只替换"源方言层"。

---

## 一、能导什么

| 模块 | 竞驰源表 | 管家婆目标 | 通道 |
|---|---|---|---|
| 往来单位 | `T_base_wldw_inner` | `btype` | 官方过程 `p_hh_BasicInsertB_Commodity` |
| 仓库 | `t_base_storage_inner` | `Stock` | 官方过程 `p_hh_BasicInsertK_Commodity` |
| 职员 | `t_base_employees` | `employee` | 官方过程 `p_hh_BasicInsertE_Commodity` |
| 商品（含分类、双单位） | `t_base_goods_inner` | `ptype` + `xw_PtypeUnit` | 官方过程 `p_hh_BascInsertP_Commodity` |
| 库存结存 | `t_base_goodsstock` | `IniGoodsStocks` | 官方过程 `p_hh_ModInitGoodsStocks_SNMng_Package` |
| 客户价格跟踪 | `t_base_price` | `xw_P_PriceFollow` | 官方过程 `p_hh_ImportPtypePriceGZ` |
| 条码 | `t_base_GoodsBar` | `xw_PtypeBarCode` | 直写（官方过程不收条码） |
| 扩展价格 | `price4/5`、`vipprice`、`specialprice` | `xw_P_PtypePrice` + 自定义价格类型 `0119~0122` | 直写 |
| 扩展辅助单位 | `unit3/unit4` | `xw_PtypeUnit`（`Ordid=2/3`） | 直写 |

**为什么不全直写表**：管家婆的编号必须级联（一级 5 位、二级 = 父编号 + 5 位），
`soncount/psonnum/bsonnum` 等字段被客户端树读取，父引用、拼音、子级计数都靠官方过程维护。
走官方过程，导入后客户端能正常展开树、能直接开单。

## 二、环境要求

- 源：SQL Server 2008+（竞驰账套所在实例），本机实测 `DESKTOP-8P5G8VQ\SQLEXPRESS`
- 目标：SQL Server 2016（管家婆辉煌 TOP15），本机实测 `DESKTOP-8P5G8VQ\SQLSERVER`
- 客户端：Windows + 管家中 ODBC 驱动（17/18 或 Native Client 11），工具启动时自动按服务器版本选驱动
- 不需要安装 Python；exe 为免安装单文件

## 三、使用步骤

1. 打开 `竞驰管家婆一键资料互传.exe`
2. **源库**：实例、库名（默认 `kspcDefault`）、sa 密码 → 点"测试连接"，
   看到"竞驰账套已识别：ProductCode=kspc 版本=mS.D.08.8.1.1.000" 即正常
3. **目标库**：实例、账套库名（默认 `HH15new`）、sa 密码 → 点"测试连接"，
   看到"管家婆账套可用：xxx 张表" 即正常
4. 勾选模块（默认全选），首次建议保留"导入前自动备份目标 13 表"
5. 点"开始一键导入"，观察日志
6. 导入完成后重开管家婆，进"基本信息"检查单位/商品/仓库/职员

## 五、已经踩过并固化的坑（重要）

1. **官方过程参数语义是反的**：`@FullName` 是**编号**、`@UserCode` 是**全名**。
   传反的后果是管家婆里"编号"列显示商品名。
2. **父引用必须用过程返回的树编号**：官方过程按库内现状续排（库里已有 883 个单位时，新单位是 `00017`），
   不是预期的 `00001`。子级必须用 `@rt OUTPUT` 的真实编号，否则 `rc=-17 / -3 / -5 父类不存在`。
3. **期初要未开账**：`sysdata.iniover=1` 时官方过程拒收期初应收应付（`rc=-13`）与库存期初。
   工具导入前自动置 0，`finally` 恢复。
4. **仓库必须平铺**：带子级的仓库在管家婆里是"类仓库"，库存挂不上（`rc=-7`）。
5. **商品分类单位写"无"**：竞驰分类行 `unit1` 为空，管家婆分类单位是 `无`，传空触发 `rc=-28`。
6. **辅助单位与换算率同进同退**：竞驰空值常以 `0` 落库，字符串 `"0"` 非空会触发 `rc=-28`；
   工具在 `unit2` 为空或换算率为 0 时把两者同时清空。
7. **条码 `UnitID` 必须数字串**：写单位名会让客户端 `fn_GetBarCodeStr` 报 245 类型转换错误。
8. **导入后归位**：四表 `updatetag=10000` + `xw_BaseUpdateTag=0`，否则客户端增量过滤导致树空白。
9. **pyodbc `autocommit` 必须是 `connect()` 关键字参数**，写进连接串无效，连接关闭时数据全部回滚。

## 六、实测结果（2026-11-05）

源：`kspc_test`（`kspcDefault` 34MB 副本 + 造入测试资料）
目标：`HH15new`（基线 btype 883 / ptype 24729 / Stock 9 / employee 3 / IniGoodsStocks 6204）

| 模块 | 条数 | 成功 |
|---|---|---|
| 往来单位 | 5 | 5 |
| 仓库 | 3 | 3 |
| 职员 | 2 | 2 |
| 商品 | 4 | 4 |
| 库存结存 | 4 | 4 |

| 条码 | 4 | 4 |
| 扩展价格 | 4 | 4 |
| 扩展辅助单位 | 2 | 2 |

**失败 0 条。** 编号级联（`00017` → `0001700001`）、父层级、`sonnum=2`、四档价格映射、库存数量金额全部核对一致。

## 七、已知限制

- 竞驰仓库层级被拍平（管家婆库存不能挂类仓库）
- 品牌（`pp_id`）、部门（`depid`）、季节（`jj_id`）、辅助属性暂不导入
- 期初应收应付导 `*00` 字段；运行余额（`ystotal` 等）属历史发生额，不导
- 反向（管家婆 → 竞驰）未实现：竞驰表 `NOT NULL` 列极多（商品 113 列），反向补默认值工作量大

## 九、与「管家婆TOP15双向直导工具 v3.1」的关系

本工具是 v3.1 的**平行扩展**：v3.1 处理 Excel / 千业 Bas / 管家婆↔千业双向；
本工具把"源方言"换成竞驰管理通，其余（官方过程通道、备份回滚、清缓存、驱动矩阵）完全复用 v3.1 的 `gpj_top15_core.py`。

后续新增软件只需实现一个适配器模块（`load_*` 读取 + `import_from_db` 编排），
核心通道不需要改动。
