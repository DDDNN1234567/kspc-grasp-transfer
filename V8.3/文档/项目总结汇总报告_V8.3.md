## 三、P1-1：官方错误码原文与 12 条反向用例

- `error24`：竞驰帮助文档解包后确认，竞驰序列号只有“强制管理/非强制管理”，没有“大码进细码出（`pgManCode`）”；源表无同义字段。

## 五、P1-5：人工产品版本/行业 + schema 双门禁

### 5.1 第一道人工门禁

`PRODUCT_PROFILES` 给辉煌 TOP15 五档产品版本：

财贸两档：`财贸双全`、`财贸双全Ⅱ TOP+`。行业覆盖：通用 / 食品 / 五金建材 / 电脑通讯 / 布匹皮革。GUI 在目标卡片下方新增“人工产品版本”和“行业”两个下拉，切换目标时自动换可用版本；提示语明确“第一道人工门禁；目标 schema 为第二道门禁，只能收紧不能放宽”。

### 5.2 第二道 schema 门禁

`version_gate(conn, target, product_version, industry, rows)` 输出三段：

- 人工：当前选择允许哪些能力；源数据实际命中 > 0 且人工不允许时拦截。
- schema：目标库 `ptype` 是否有对应列；缺列拦截。
- 生效：`人工选择允许 AND schema 存在`；不是“人工 OK 且 schema OK”的合取。

实跑 HH15new / 通用版 / 通用：

```text
GATE {'serial': False, 'taste': False, 'sideunit': True,
      'pgman': False, 'shelflife': True} blocked=False
```

源数据 2 行商品 `serialType` 全 0，命中的能力没有被“源数据没用就不拦”以外的理由阻断；未阻断。这里的 `False` 是“该版本不提供该能力”，不是“校验失败”。

## 七、P2-4：逐商品出库日期

### 7.1 代码接入

- `load_first_outdates(cur)`：连竞驰源，`SELECT ID, code FROM t_base_goods_inner` 建映射；对 `t_dj_p_sale / t_dj_p_sale_retail / t_dj_p_sale_join` 取 `MIN(outdate) GROUP BY goodsid`，过滤 `outdate IS NULL`、空串、`isred=1`。
- `expiry_rows(goods_rows, outdate_map, default_out_date)`：逐行算有效期至，`mode=per_goods`（有真实出库日期）或 `trial`（无数据明确标注试算）；公式 `出库日期 + LifeDay - 1`，`LifeDay=0` 按 1。
- `run_audit` 的 `expiry.mode` 由 `data_rows>0` 决定，报告写“试算 N 行”，不伪装成已接入。

### 7.2 事务内验证

真实源库 `t_dj_p_sale` 仅 1 行，`outdate=''`，`t_dj_p_sale_retail`/`t_dj_p_sale_join` 各 0 行。为验证代码路径，在事务内把该行 `outdate` 临时改为 `2026-11-06`，调用 `load_first_outdates` 得：

```text
MAP_IN_TX {'00101': '2026-11-06'}
EXPIRY [{'code':'00101','life':150,'out_date':'2026-11-06',
         'end_date':'2027-04-04','mode':'per_goods'}]
```

回滚后 `outdate` 恢复为 `''`，源库未变化。说明“接入代码”可跑通；但真实业务数据没有出库日期，V8.3 实跑仍为：

```text
EXPIRY trial 0 2
```

即 2 行商品走试算，报告中明确注明，不冒充已全量接入。
