## 三、P1-1：官方错误码原文与 12 条反向用例

从 `HH15new` 的 `OBJECT_DEFINITION` 完整导出 `p_hh_BascInsertP_Commodity` 到 `_工作区\v83_p_hh_BascInsertP_Commodity.sql`，逐条读 `SET @errorValue` 原文与 `RETURN` 值。此前把千业 `SjShuju.sql` 的同名标签当成商品导入语义，是错语境；千业的 `error24/25/31/38` 分布在反审核、序列号反审核、销售单插入分支，与辉煌官方导入过程不是同一语义空间。V8.3 一律以辉煌官方原文为准。

12 码全部用官方原文：error6/15/20/21/24/25/28/29/30/31/37/38。`error15` RETURN 是 -18；`error20/21` 共用 -23；`error24/25/31/38` 分别为 -24/-25/-31/-38。`precheck_selftest()` 实跑 **12/12 全部命中**。

源字段边界：`error24` 需 `pgManCode`，竞驰无此概念；`error25` 需目标 `Pos_Dummy_Ptype.pusercode`；`error31` 需 `F_PRODUCT_TRADE()=4` 且父级 `KWManCode=1`，竞驰无口味管理概念。三条是“代码可判、数据靠注入/目标现状”，不是源表全可判。

## 四、P1-2：单据/盘点/调价分项立项

三类分项：单据 6 模板、盘点 1、调价 1；全部“只读校验通过；写入未开放”。只读校验器不等于模块已开放写入，本报告不把“只读通过”写成“单据导入已上线”。

## 五、P1-5：人工产品版本/行业 + schema 双门禁

GUI 在目标卡片下方新增“人工产品版本”和“行业”下拉；`PRODUCT_PROFILES` 辉煌五档、财贸两档；`version_gate` 生效条件为 `人工选择允许 AND schema 存在`，schema 只能收紧不能放宽。实跑 `blocked=False`。这里的 `False` 是“该版本不提供该能力”，不是“校验失败”。

## 六、P1-6：`BasPTypeBarMx.bz` 决策与 9 模块复跑

决策“不迁移”：源库 `qysrc_qys` 缺该列；9 模块条码 SQL 只读 `PTypeID/BarCode/IndexID`，不引用 `bz`；由千业 UpdateDB 自行升级。`schema_drift` 拆 `missing` 与 `accepted`，实跑 51 新增 / 0 阻断 / 1 接受。

隔离库 `HH15v83test` 9 模块复跑 0 失败。before/after：btype 1→396、ptype 1→3872、Stock 1→2、employee 1→3、期初 0→2743、价格 0→21304、条码 0→3804、辅助单位 0→3871、价格跟踪 0→184840；回滚前缀 `_impbak_20261107100539`。

## 七、P2-4：逐商品出库日期

`load_first_outdates` + `expiry_rows` 接入；事务内把源库 1 行 `outdate` 临时改 `2026-11-06`，得 `per_goods`、`end_date=2027-04-04`；回滚后 `outdate=''`，源库未污染。真实源库无有效出库日期，V8.3 实跑 `EXPIRY trial 0 2`，不冒充全量接入。
