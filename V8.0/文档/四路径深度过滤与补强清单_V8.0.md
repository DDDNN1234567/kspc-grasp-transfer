## 一、结论先行

四路径的价值不在“模板数量多”，而在三件事：

1. **官方字段口径可以直接推翻工具里的经验映射**。辉煌官方过程写的是 `UsefulLifeDay`、`SNManCode`、`PJobManCode`，不是 `ShelfLife`、`bBlockNo`；财贸的 `bBlockNo` 是“管理批号”，`ManSerialNum` 才是“序列号管理”。V8.0 现行 `bBlockNo ← serialType` 属于把序列号当批号，必须返工。
2. **双版本不是同一套字段换个库名**。财贸桌面端读 `ShelfLife`，线上/手机端 SQL 写 `UsefulLifeDay`；辉煌只认 `UsefulLifeDay`。同一源字段 `bzDateNum` 在两端要落到不同列，不能只改财贸。
3. **四路径还能补三类工程能力**：官方校验码移植成预检、官方行业模板扩成可选导入模块、备份/升级包变成版本回归与兼容门禁。这三类比继续加界面卡片更能提升可交付性。

按双版本语义复核，V8.0 现有 37 项中 **34 项可闭环、3 项需返工**；返工项集中在 P0-4，不影响 P0-3 回滚、P1 隔离自检、P2 界面与千业双向的既有结论。

## 三、决定性证据

### 3.1 辉煌官方过程：有效期、序列号、批次是三列

`p_hh_BascInsertP_Commodity` 第 349 行不是直接 INSERT，而是 `EXEC @RetValue = p_hh_BasicInsertP`；`p_hh_BasicInsertP`（LEN 8,866）第 170–184 行 `INSERT INTO [ptype]` 的列清单包含：

- `UsefulLifeDay`，值来自 `@LifeDay`；
- `SnManCode`，值来自 `@SnManCode`；
- `PJobManCode`，值来自 `@PJobManCode`；
- `SideUnit`、`pgManCode`、`KWManCode`、`IsWeight`、`DefBtypeID`、`PoolDiscount`、`DefaultTax`、`AllowModifyPrice`、`sourcewayzz/wg/ww` 等。

全程没有 `ShelfLife`、没有 `bBlockNo`。因此辉煌侧的“保质期/序列号/批次”不能套财贸列名。

### 3.2 财贸字段：`bBlockNo` 是批号，`ManSerialNum` 是序列号

`F:\GraspServer\CMSQ\UpdateFileDown\22.0\V220UpdateServerPack20220831.sql`：

- 第 42/47 行 `CAST(p.bBlockNo AS INTEGER) AS bBlockNo`、`ISNULL(p.ManSerialNum,0) AS bSerialNum`；
- `AfterSaleService.dll` 查询串：`p.bBlockNo AS ManageBlockNo, p.ManSerialNum AS ManageSerialNo`；
- `BaseInfoManage.dll`：`UPDATE dbo.ptype SET costmode = 3, bBlockNo = 1, TakeOut = 1 ...`，即批号管理与成本算法联动；
- `BaseInfo.dll` 窗体控件：`edtShelfLife`、`chkTakeOut`、`edtBatchBlockNo`；
- `OnlinePhoneManage.dll`：`@LifeMonth=UsefulLifeMonth, @LifeDay=UsefulLifeDay`。

结论：**财贸桌面端保质期读 `ShelfLife`，线上/手机端走 `UsefulLifeDay`；`bBlockNo` 只表示管理批号，`ManSerialNum` 才表示序列号管理。** 现行 `bBlockNo ← serialType` 语义错误。

### 3.3 竞驰源字段：只有两个相关列，且都不是“批号”

`kspcDefault.t_base_goods_inner` 共 117 列，与序列/批次/日期相关的只有：

- `serialType`（int）：竞驰帮助《序列号使用.htm》说明其界面含“序列号强制管理 / 序列号非强制管理”，属于**序列号使用类型**；
- `bzDateNum`（int）：保质期天数。

源表没有独立“管理批号”列。把 `serialType` 非 0 写成 `bBlockNo=1`，等于给所有启用序列号的商品误开“管理批号”；而真正的序列号列 `ManSerialNum` 反而一直是 0。

### 3.4 官方模板与过程校验：V8.0 只用了模板列，没移植错误码

- `食品/电脑通讯/辉煌2/五金建材(商品).xml` 的 `Target="ptype"`、`KeyField="PTypeID"`、`StoreName="p_hh_BascInsertP_Commodity"`，字段含 `有效期(天)→LifeDay`、`条码→UCode`、`零售价→SalePrice`、`预设售价1/2/3→PrePrice1/2/3`、`配送价→SendPrice`、`最近折后进价→BuyDiscountPrice`、`最低售价→LowSalePrice`、`默认税率→defaulttax`、`前台议价→allowprice`、`启用批次→pjobmancode`；
- `电脑通讯` 独有 `序列号管理→snManCode`；
- `食品/辉煌2/五金建材` 独有 `是否自制→sourcewayzz`、`自制周期→sourcewayzzDay`、`是否外购→sourcewaywg`、`外购周期→sourcewaywgDay`；
- `食品` 另有 `口味管理→kwManCode`；`五金建材` 独有 `副单位→SideUnit`。

官方校验码（`p_hh_BascInsertP_Commodity` 外层）：error6 序列号管理但成本算法不在 (0,3,4)、error15 父级属性不符、error20/21 全名/编号重复、error25 与 POS 临时商品冲突、error28/29 辅助单位与换算不匹配、error30 有辅单位无基本单位、error31 口味管理与产品线冲突、error37/38 辅助单位重复；内层 `p_hh_BasicInsertP` 另有 error101(-1052)/102(-1133)/103(-1134)/104(-1135)/105(-1124)/108(-1846)/109(-1847)/110(-110)/111(-111)/112(-1125)/114(-1128)。V8.0 目前没有把这些错误码做成逐行预检。

### 3.5 财贸官方模板：27 列只覆盖档案，不覆盖序列号

`F:\GraspServer\CMSQ\BackUp\存货档案.xls` 表头 27 列：

`父项编号|存货编号|存货全名|简名|助记码|规格|型号|产地|条码|基本单位|辅助单位1|单位关系1|入库默认|出库默认|参考零售价|最低售价|一级批发价|二级批发价|三级批发价|四级批发价|五级批发价|备注|成本计价|管理批号|近效期先出库|核算方法|参考成本`

其中只有“管理批号”“近效期先出库”，没有“序列号管理”。这解释了为什么只看 27/33/35 项模板会漏掉 `ManSerialNum`：**模板通过不等于序列号字段落库**。

## 四、P0 返工项（必须先改，否则不能称双版本完整）

### P0-1 财贸：`serialType` 不能写 `bBlockNo`

- 现状：`kpsc_to_cmsg.py:820-822` 写 `"bBlockNo": 1 if i(r.get("serialType")) else 0`；专项校验 `:1106-1146` 也按这个期望值比对。
- 缺口：`bBlockNo`=管理批号，`serialType`=序列号使用类型；源表无批号列，正确结果应是 `bBlockNo=0`，同时 `ManSerialNum=1`（启用序列号）。
- 动作：`bBlockNo` 固定 0（除非后续确认竞驰另有批号来源）；新增 `ManSerialNum = 1 if serialType else 0`；`SerialConfig` 按竞驰“强制/非强制”取值确认后写入；同步改字典、专项校验与模板说明。
- 验收：源 `serialType=1` 的隔离库样本，目标 `bBlockNo=0`、`ManSerialNum=1`；财贸客户端“管理批号”不勾、“启用序列号管理”勾选；`p_hh` 侧 error6 不触发。

### P0-2 辉煌：`bzDateNum` / `serialType` 没有传进官方过程

- 现状：`gpj_top15_core.py:543-570` 的 `call_goods` 已声明 `LifeDay`、`snManCode`、`pjobmancode` 等参数；但 `gpj_kspc_adapter.py:712-726` 调用时只传了 `costmode`、`price/1/2/3`、`sendprice`、`lowprice`、`unit1`、`defaulttax`，没有 `life`、`snmancode`、`pjobmancode`；`load_goods` 的列清单也没有 `serialType`、`bzDateNum`。
- 缺口：真实库 `HH15testV4` 26,920 行商品，`UsefulLifeDay`、`SNManCode`、`PJobManCode` 全为 0；现行通道下这三个官方字段实际未落库。
- 动作：`load_goods` 增加 `serialType`、`bzDateNum`；`call_goods` 传 `life=<bzDateNum>`、`snmancode=<0/1/2 映射>`、`pjobmancode=0`；若竞驰后续补批次来源，再写 `PJobManCode`。
- 验收：辉煌隔离库样本 `UsefulLifeDay=150`、`SNManCode=1`、`PJobManCode=0`；`f_CountUsefulEndDate` 可按 `出库日期 + LifeDay - 1` 算出有效期至；官方过程返回 rc≥0。

### P0-3 财贸：保质期要双写 `ShelfLife` 与 `UsefulLifeDay`

- 现状：只写 `ShelfLife=150`，`UsefulLifeDay=0`。
- 缺口：桌面端 `BaseInfo.dll` 读 `ShelfLife`；线上/手机端 SQL 写 `UsefulLifeDay`。只写一个，另一端会显示 0。
- 动作：`bzDateNum` 同时写 `ShelfLife` 与 `UsefulLifeDay`；若担心重复，可把 `UsefulLifeDay` 作为官方主字段、`ShelfLife` 作为桌面兼容字段，并在验收中明确两者同值。
- 验收：`财贸测试demo.ptype` 同一商品两列均 150；桌面“存货档案”和线上/手机端均显示 150。

## 八、验收总口径

- **字段层**：不只看模板列；每个“模板未列但源有值”的字段必须有目标列、独立校验和一条真实回读。
- **版本层**：同一源字段在财贸/辉煌的不同目标列必须分别声明；不支持的版本要拦截，不静默丢字段。
- **证据层**：每个结论至少有“官方文件/过程/客户端字段/真实回读”中的两类证据；不接受“帮助里没写所以不存在”。
- **回归层**：P0 修复后重跑财贸 34+247、辉煌 14 项、千业 9 模块；三项全过才可把完成度改为 37/37。
